# 产品命名方案

## 命名约束

产品不只是文字转日历，还包含 Due、订阅、同步、Widget 和可选 AI。因此名字不应把产品锁死在 `calendar`、`text` 或某一种输入方式上。

目标名字应：

- 能同时容纳时间安排和截止事项。
- 英文易读、易输入、适合 GitHub 仓库和桌面 App。
- 不依赖“AI”或“智能”等短期卖点。
- 适合单用户、自托管和开源语境。
- 在正式采用前单独检查商标、域名、GitHub 组织名、App Store 和 npm/PyPI 冲突。

## 候选名称

| 名称 | 含义 | 优点 | 风险或歧义 |
| --- | --- | --- | --- |
| **Dayweave** | 把一天中的日程和 Due 编织在一起 | 有产品感，范围不窄，适合长期扩展 | `weave` 的含义需要品牌说明；需查现有项目 |
| **Dayloom** | day + loom，构建个人时间织物 | 独特、温和、适合本地优先工具 | `loom` 对部分用户不直观 |
| **Timefold** | 把不同来源的时间折叠到一处 | 能表达聚合和跨来源 | 可能被理解为时间管理课程或已有产品 |
| **Morrowline** | 面向明天和未来事项的一条线 | 适合计划和 Due | 对“今天的日历”表达不直接 |
| **Dueframe** | 用一个框架管理 Due 和时间块 | 语义清楚、偏工具型 | 对没有 Due 需求的用户显得偏任务 |
| **Gatherday** | 收拢一天中的事项 | 亲和、容易解释 | 稍长，可能与生活方式产品混淆 |
| **Planweave** | 编织计划、日程和提醒 | 直接体现计划属性 | `plan` 类产品较多，独特性较弱 |
| **Daymark** | 给重要日子做标记 | 简短、容易记忆 | 现有同名产品和商标可能较多 |

## 推荐顺序

1. **Dayweave**：最能覆盖日程、Due、订阅和未来扩展，既不像纯日历，也不像纯待办。
2. **Dayloom**：更有独立产品气质，适合强调个人节奏和本地数据。
3. **Timefold**：更偏技术和聚合，适合强调多来源统一视图。

本次只把 `Dayweave` 作为工作名称写入文档，不修改仓库名和运行时显示名。名称确认后按以下顺序迁移：

1. 更新 README、API title、Web title、`setup.json` 和默认配置。
2. 更新 Python 包、Flutter bundle ID、Worker 名称和 Docker image 名称。
3. 更新 GitHub 仓库、部署域名和文档链接。
4. 保留旧环境变量和 API title 一个版本周期，并提供迁移说明。
5. 名称迁移完成后再删除兼容别名。
