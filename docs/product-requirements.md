# 产品需求

## 1. 产品目标

把“日程”和“Due”放进同一个个人工作台，减少在日历、待办、课程表和提醒应用之间来回切换。

产品优先级是：可自用、数据可控、离线可靠、部署简单、扩展不破坏核心模型。它不是团队协作产品，也不以账号体系或 AI 炫技为中心。

## 2. 用户和运行模式

### 个人用户

- 在 Android、macOS、Windows 查看和编辑自己的事项。
- 没有网络时仍能工作。
- 可以订阅课程表、活动日历和公开 ICS 地址。
- 可以把自然语言变成候选日程或 Due，确认后才保存。
- macOS 上通过 Widget 快速查看今天和近期重点。

### 自托管实例所有者

- 部署一个自己的同步服务。
- 使用一个实例级 token 连接设备。
- 通过配置文件修改域名、端口、时区、AI、ICS 和存储参数。
- 能导出和备份全部数据。

### 开发者

- 添加 Parser、Importer 或 AI Provider 时无需修改 Item 核心模型。
- 能通过稳定接口替换本地存储、同步传输和通知实现。
- 能用测试 fixture 验证扩展，不依赖真实第三方账户。

## 3. 核心概念

- **Item**：已经确认、可保存、可同步的正式事项。
- **CandidateItem**：规则解析器或 AI 生成的未确认候选项。
- **Event**：有开始和结束时间的 Item。
- **Task / Due**：有截止时间的 Item，可完成或取消。
- **Collection**：本地列表、外部订阅或外部日历的容器。
- **Subscription**：一个 ICS URL 及其刷新状态。
- **Outbox**：本地离线变更等待同步的队列。

## 4. 功能范围

### 4.1 日程

- 创建、查看、编辑、软删除。
- 开始时间、结束时间、时区、全天、地点、备注。
- 重复规则和例外日期。
- 提醒开关和提醒时间。
- 来源标记：`local`、`ics`、`ai`、`google`、`microsoft`、`lark`、`plugin`。
- 日历工作台可在单日、周和月三种视图之间切换，并在切换后保留当前选中日期。
- 单日和周视图使用可纵向滚动的 24 小时时间轴；周视图以日期为列，定时 Event 按起止时间占据对应区间，全天 Event 使用独立区域。
- 单日和周视图可以通过触控板手势或明确的缩放控件调整每小时显示高度；缩放只改变视觉密度，不修改事项时间。
- 时间轴最小密度应允许在当前最小高度基础上再缩小到三分之一，便于在桌面窗口中同时浏览更多小时。
- 月视图按周分行、按日分列，只列出事件摘要，不显示纵向时间轴；溢出事件以数量入口展开。
- 月视图最左侧显示 ISO 周序号；点击周序号进入该周的周视图。周起始日遵循 locale，`zh-CN` 默认周一。
- 标签可以分配颜色；同一标签在列表、日历和编辑器中使用一致颜色，没有显式颜色时使用稳定的默认色。
- 日程和 Due 可以按一个或多个标签筛选与分组；日历工作台的筛选状态在切换日/周/月视图时保留。

### 4.2 Due

- 创建、查看、编辑、完成、取消、软删除。
- 截止时间、优先级、标签、备注和提醒。
- 列出逾期、今天、未来和已完成 Due。
- 未完成 Due 固定显示在日历工作台顶部；有截止时间的 Due 在日/周时间轴中占用截止前 30 分钟，并在月视图中列为事项摘要。
- 完成操作必须幂等，重复点击不能产生额外变更。

### 4.3 文本解析和 AI

- 输入一段文本，输出零个或多个候选项。
- 用户可以在设置中添加或导入 OpenAI-compatible Provider 配置，包括 API 地址、模型和可选请求参数，并单独录入 API key。
- API key 只保存在当前设备的平台安全存储中，不进入 SQLite、同步、备份、日志或候选 reasoning；API 地址、模型等非敏感设置可保存在客户端设置中。
- 设置页提供连接测试、Provider 启停和配置校验；Provider 不可用或未配置时，本地规则 Parser 和日历 CRUD 仍可使用。
- 大模型负责把一段需求拆分成一个或多个 Event、Task 候选项，不直接创建正式事项。
- 候选项必须包括类型、标题、时间、置信度和来源文本位置。
- 可建议提醒，但提醒也必须由用户确认。
- 候选项可以编辑、删除、拆分或合并。
- 未确认候选项不进入正式 Item 表，不进入同步 outbox。

### 4.4 外部 ICS 订阅

- 添加、启用、暂停、刷新和删除订阅。
- 订阅内容导入只读 Collection。
- 保存最近成功时间、错误信息、ETag 和源哈希。
- 同一订阅重复刷新不得重复创建事项。
- 外部事项发生变化时按稳定外部 ID 更新；消失时软删除或标记已移除。

### 4.5 同步

- 客户端本地优先，所有本地编辑先写 SQLite。
- 变更进入 outbox，网络恢复后增量 push。
- 客户端用 cursor pull 其他设备的变更。
- 第一版采用按 `updated_at` 的最后写入胜出。
- 删除也是同步变更，使用 `deleted_at` 保留墓碑。
- 没有服务器时仍能完整使用本地功能。

### 4.6 Widget 和提醒

- 客户端本地调度通知，服务端不承担第一版通知调度。
- 主 App 输出稳定的 Widget snapshot JSON。
- Widget 只读快照，不直接读取服务器或执行复杂编辑。

### 4.7 桌面窗口控制

- 透明度、始终置顶和交互锁定的主控件集中放在设置页的“桌面窗口”分区，不占用日历工作台常驻空间。
- macOS 和 Windows 桌面客户端提供窗口透明度调节；透明度使用明确的滑块或步进控件，保留可读性下限，并按设备保存。
- 桌面窗口可以切换为始终置顶；该状态只属于本机窗口偏好，不参与跨设备同步。
- 桌面窗口可以进入交互锁定模式：窗口保持可见，鼠标点击和滚动穿透到下一层窗口。
- 交互锁定必须有不依赖鼠标命中当前窗口的退出路径，例如全局快捷键和系统菜单入口；锁定状态不得跨进程重启保留。
- Android 不显示不适用的桌面窗口设置；不支持某项原生能力的平台必须隐藏或禁用对应控件并说明原因。

## 5. 关键用户流程

### 单机使用

1. 启动 App，创建或导入本地 Collection。
2. 创建 Event 或 Task。
3. 本地保存并安排提醒。
4. 完成或编辑后生成 outbox 记录，但没有服务器时保持待同步状态。

### 候选确认

1. 输入自然语言。
2. Parser 或 AI 返回 `CandidateItem[]`。
3. 用户逐项编辑、接受、拒绝或拆分。
4. 接受的候选项转换为正式 `Item`。
5. 只有正式 Item 写入本地数据库和同步 outbox。

### AI 拆分创建

1. 用户在设置中选择 Provider，填写 API 地址和模型，并将 API key 保存到平台安全存储。
2. 用户输入包含多个安排或 Due 的自然语言需求。
3. Provider 返回结构化候选项；客户端完成 schema、时间和类型校验。
4. 用户逐项修改、拆分、合并、接受或拒绝候选项。
5. 仅被确认的候选项转换为正式 Item；部分候选失败不允许静默创建。

### 桌面日历工作台

1. 用户从月视图定位日期，或点击周序号进入对应周视图。
2. 用户在单日或周视图滚动时间轴，并缩放每小时显示高度。
3. 用户在设置页的“桌面窗口”分区调整透明度和置顶状态，在参考其他资料时保持日历可见。
4. 用户启用交互锁定后，点击穿透到下层窗口；通过全局快捷键或系统菜单解除锁定。

### 多设备同步

1. App 使用 `server_url` 和单一实例 token 配置同步服务。
2. 本地变更进入 outbox。
3. 同步器 push 未发送变更。
4. 同步器 pull 新 cursor 后应用远端变更。
5. 冲突按最后写入胜出，冲突记录保留在日志中。

### ICS 订阅

1. 用户输入 ICS URL 和显示名称。
2. 服务端验证并创建只读 Collection。
3. 定时任务或手动刷新源。
4. Parser 将 VEVENT 转换成 `source=ics` 的 Item。
5. App 展示刷新时间和错误状态。

## 6. 非目标

第一阶段明确不做：

- 多用户注册、组织、成员、角色和权限矩阵。
- 多人协作、共享编辑和实时协同。
- 付费、计费、插件市场和广告。
- 会议室、资源排期、多人空闲时间协调。
- 服务端统一通知调度。
- AI 自动写入正式 Item。

## 7. 产品验收标准

### 本地 MVP

- 无服务器、无 AI key 时，用户可以完成 Event 和 Task 的增删改查。
- 关闭网络后仍能使用，重新联网不丢本地数据。
- JSON 导出后可以在另一台设备导入并保留 ID、时间和状态。

### 自托管同步

- 用户只修改配置文件并执行一条部署命令即可启动实例。
- macOS 创建的事项可以在 Android 或 Windows 拉取。
- 离线编辑后恢复网络可以自动同步。
- 错误响应可定位到具体变更，不会静默丢数据。

### 候选和 AI

- 一段文本可以生成多个候选项。
- Event 和 Task 的字段语义不混用。
- 用户拒绝候选项后不会出现正式 Item。
- 没有 AI 配置时，规则 Parser 和核心本地功能仍可用。
- API key 不出现在客户端数据库、同步 payload、导出文件和日志中。
- AI 输出无效、超时或连接失败时不创建正式 Item，并向用户显示可恢复的错误。

### 日历和桌面窗口

- 单日和周视图的 Event 位置与起止时间一致；滚动和缩放不改变 Item 数据。
- 月视图可浏览每天的事件摘要，点击任一周序号进入正确的周视图。
- 透明度和置顶状态在同一设备重启后恢复；交互锁定在重启后自动关闭。
- 交互锁定时点击能到达下层窗口，并始终可以不依赖当前窗口点击来解除锁定。

### 订阅和 Widget

- 一个公开 ICS URL 能成功显示事项。
- 刷新失败时界面能看到最近错误和上次成功时间。
- Widget 只展示快照内容，不会因为服务器暂时不可用而崩溃。
