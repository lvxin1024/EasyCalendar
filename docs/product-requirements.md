# 产品需求

## 1. 产品目标

把“日程”和“Due”放进同一个个人工作台，减少在日历、待办、课程表和提醒应用之间来回切换。

产品优先级是：可自用、数据可控、离线可靠、部署简单、扩展不破坏核心模型。它不是团队协作产品，也不以账号体系或 AI 炫技为中心。

## 2. 用户和运行模式

### 个人用户

- 在 Android、macOS、Windows 查看和编辑自己的事项。
- 没有网络时仍能工作。
- 可以订阅课程表、活动日历和公开 ICS 地址。
- 可以把自然语言变成候选日程或 Due，确认后才保存。
- macOS 上通过 Widget 快速查看今天和近期重点。

### 自托管实例所有者

- 部署一个自己的同步服务。
- 使用一个实例级 token 连接设备。
- 通过配置文件修改域名、端口、时区、AI、ICS 和存储参数。
- 能导出和备份全部数据。

### 开发者

- 添加 Parser、Importer 或 AI Provider 时无需修改 Item 核心模型。
- 能通过稳定接口替换本地存储、同步传输和通知实现。
- 能用测试 fixture 验证扩展，不依赖真实第三方账户。

## 3. 核心概念

- **Item**：已经确认、可保存、可同步的正式事项。
- **CandidateItem**：规则解析器或 AI 生成的未确认候选项。
- **Event**：有开始和结束时间的 Item。
- **Task / Due**：有截止时间的 Item，可完成或取消。
- **Collection**：本地列表、外部订阅或外部日历的容器。
- **Subscription**：一个 ICS URL 及其刷新状态。
- **Outbox**：本地离线变更等待同步的队列。

## 4. 功能范围

### 4.1 日程

- 创建、查看、编辑、软删除。
- 开始时间、结束时间、时区、全天、地点、备注。
- 重复规则和例外日期。
- 提醒开关和提醒时间。
- 来源标记：`local`、`ics`、`ai`、`google`、`microsoft`、`lark`、`plugin`。

### 4.2 Due

- 创建、查看、编辑、完成、取消、软删除。
- 截止时间、优先级、标签、备注和提醒。
- 列出逾期、今天、未来和已完成 Due。
- 完成操作必须幂等，重复点击不能产生额外变更。

### 4.3 文本解析和 AI

- 输入一段文本，输出零个或多个候选项。
- 候选项必须包括类型、标题、时间、置信度和来源文本位置。
- 可建议提醒，但提醒也必须由用户确认。
- 候选项可以编辑、删除、拆分或合并。
- 未确认候选项不进入正式 Item 表，不进入同步 outbox。

### 4.4 外部 ICS 订阅

- 添加、启用、暂停、刷新和删除订阅。
- 订阅内容导入只读 Collection。
- 保存最近成功时间、错误信息、ETag 和源哈希。
- 同一订阅重复刷新不得重复创建事项。
- 外部事项发生变化时按稳定外部 ID 更新；消失时软删除或标记已移除。

### 4.5 同步

- 客户端本地优先，所有本地编辑先写 SQLite。
- 变更进入 outbox，网络恢复后增量 push。
- 客户端用 cursor pull 其他设备的变更。
- 第一版采用按 `updated_at` 的最后写入胜出。
- 删除也是同步变更，使用 `deleted_at` 保留墓碑。
- 没有服务器时仍能完整使用本地功能。

### 4.6 Widget 和提醒

- 客户端本地调度通知，服务端不承担第一版通知调度。
- 主 App 输出稳定的 Widget snapshot JSON。
- Widget 只读快照，不直接读取服务器或执行复杂编辑。

## 5. 关键用户流程

### 单机使用

1. 启动 App，创建或导入本地 Collection。
2. 创建 Event 或 Task。
3. 本地保存并安排提醒。
4. 完成或编辑后生成 outbox 记录，但没有服务器时保持待同步状态。

### 候选确认

1. 输入自然语言。
2. Parser 或 AI 返回 `CandidateItem[]`。
3. 用户逐项编辑、接受、拒绝或拆分。
4. 接受的候选项转换为正式 `Item`。
5. 只有正式 Item 写入本地数据库和同步 outbox。

### 多设备同步

1. App 使用 `server_url` 和单一实例 token 配置同步服务。
2. 本地变更进入 outbox。
3. 同步器 push 未发送变更。
4. 同步器 pull 新 cursor 后应用远端变更。
5. 冲突按最后写入胜出，冲突记录保留在日志中。

### ICS 订阅

1. 用户输入 ICS URL 和显示名称。
2. 服务端验证并创建只读 Collection。
3. 定时任务或手动刷新源。
4. Parser 将 VEVENT 转换成 `source=ics` 的 Item。
5. App 展示刷新时间和错误状态。

## 6. 非目标

第一阶段明确不做：

- 多用户注册、组织、成员、角色和权限矩阵。
- 多人协作、共享编辑和实时协同。
- 付费、计费、插件市场和广告。
- 会议室、资源排期、多人空闲时间协调。
- 服务端统一通知调度。
- AI 自动写入正式 Item。

## 7. 产品验收标准

### 本地 MVP

- 无服务器、无 AI key 时，用户可以完成 Event 和 Task 的增删改查。
- 关闭网络后仍能使用，重新联网不丢本地数据。
- JSON 导出后可以在另一台设备导入并保留 ID、时间和状态。

### 自托管同步

- 用户只修改配置文件并执行一条部署命令即可启动实例。
- macOS 创建的事项可以在 Android 或 Windows 拉取。
- 离线编辑后恢复网络可以自动同步。
- 错误响应可定位到具体变更，不会静默丢数据。

### 候选和 AI

- 一段文本可以生成多个候选项。
- Event 和 Task 的字段语义不混用。
- 用户拒绝候选项后不会出现正式 Item。
- 没有 AI 配置时，规则 Parser 和核心本地功能仍可用。

### 订阅和 Widget

- 一个公开 ICS URL 能成功显示事项。
- 刷新失败时界面能看到最近错误和上次成功时间。
- Widget 只展示快照内容，不会因为服务器暂时不可用而崩溃。
